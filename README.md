# Smooth Wheel Scroll for REAPER

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
![Platform: Windows x64](https://img.shields.io/badge/platform-Windows%20x64-blue)

一个原生 REAPER 扩展：把普通鼠标滚轮变成触控板那种细腻的惯性滚动——**但不改变滚轮原本做什么**。

[English](README.en.md)

<p align="center">
  <img src="test/demo.gif" alt="Smooth Wheel Scroll 效果演示" width="880">
</p>

REAPER 几乎所有能滚动/缩放的东西都已经有对应的"滚轮动作"（动作名以
`(MIDI CC relative/mousewheel)` 结尾），这些动作本身就接受平滑的相对量。问题出在
**鼠标**：一格就是一整个 `WHEEL_DELTA` 大步，动作每格只收到一次粗跳，于是运动看起来
一顿一顿的。本插件截住滚轮，把这一格过一遍曲线模型，再把结果**分小份、按时间喂给同一条
REAPER 动作**。效果就是：**普通有格滚轮，滚出高分触控板的手感。**

---

## 它做什么（只有一件事）

> 把鼠标滚轮参数，转换成更优雅的参考动画，转给接收方——接收方是什么都行。

它驱动的一切都**由 REAPER 自己的动作完成**。插件从不自己移动视图、从不改 REAPER 状态；
它只是找到对应的动作，把动画后的相对值交给它。缩放锚点、滚动范围、用户自定义规则、步进
大小，全都保持 REAPER 原本的定义。

```
一格滚轮 ──► 本插件 ──► 同一条 REAPER 动作，分小份、按时间陆续送达
 (1 x 120)     (模型)        (View: Scroll/Zoom ... mousewheel)
```

### 会做缓动的

| 表面 | 方式 |
|---|---|
| 主视图（arrange）：滚动 + 缩放 | REAPER 自己的动作，用动画后的值重放 |
| 主视图的两条滚动条 | 竖直条：滚动；`Alt`+滚轮：竖直缩放。水平条：`Alt`+滚轮水平缩放（不带 `Alt` 的"翻页式快移"放行原生） |
| MIDI 编辑器：滚动 + 缩放 | MIDI 编辑器自己的 section 动作 |
| 所有名字带 `mousewheel` 的动作 | 同一条路径（**按动作名**匹配，所以自定义/重绑快捷键自动跟随） |
| 轨道面板（TCP）本体 | 遵从你的鼠标修饰键：默认 `Scroll TCP` → 竖直滚动；`Adjust vertical zoom` → 竖直缩放 |
| MIDI 编辑器琴键 | MIDI 编辑器自己的竖直滚动动作 |
| 调音台（MCP） | 横向滚动（把动画后的行程作为**小滚轮消息**交给 REAPER 的调音台窗口，由 REAPER 自己的 `Scroll MCP` 规则决定步长；余数跨帧累积，所以慢滚不会丢步） |
| 轨道面板两侧的宽度拖拽条 | 靠面板的那一半 → 轨道滚动；外侧一半放行（那里就是主视图） |

> 滚轮落在哪条滚动条上、或轨道面板/调音台的那个组合绑了什么，插件都**先问 REAPER**：
> 滚动条按几何识别，面板与调音台按**鼠标修饰键**（`Scroll TCP` / `Scroll MCP`）判断。
> 所以把那些组合改成别的（如 `Passthrough`），插件就**照你的选择放行**，不会硬拦。

### 刻意不碰的

* **参数类滚轮。** 任何在滚轮下**改变数值**的东西——推子、旋钮、速度、发送量、MIDI 音符
  力度、下拉框——一律原样透传，仍然一格一格精确改值。这不是手写黑名单：参数要么由 REAPER
  报出一条**非 `View` 的动作**，要么**根本不报动作**、自己在窗口内部改值。两类都不会进入动画。
* **列表控件。** 列表按整行移动，而 REAPER 的原生响应本来就是瞬时的，加缓动只会加延迟。
  所以一律放行。（这条是实测后否决的，见[§设计说明](#设计说明)。）
* **触控板、高分辨率/无级滚轮、触摸、触控笔。** 插件只改变**普通有格鼠标滚轮**（整倍数
  `WHEEL_DELTA`、非触摸注入）。其余的本来就是细粒度信号，交给 REAPER。

## 安装

Windows x64，REAPER 7（在 `7.79` 上构建与测试）。

1. 从 [Releases](../../releases) 下载 `reaper_smoothwheelscroll-x64.dll`。
2. 放进 REAPER 的 `UserPlugins` 目录：
   * **便携版：** `<REAPER>/UserPlugins/`
   * **普通安装：** `%APPDATA%\REAPER\UserPlugins\`
3. 重启 REAPER。

插件带一个设置面板，两种方式任选一种打开：

1. **Extensions 菜单** → `SmoothScroll...`
2. **Actions 窗口**里搜 `Smooth Wheel Scroll`，找到 `Smooth Wheel Scroll: settings...`，
   可以给它**绑定快捷键**；同一个键**再按一次就关闭**面板。

面板里有一个缓动总开关，5 个手感参数（滑杆）以及每个参数对应的一个旋钮；改动**即时生效、自动保存**，
关掉窗口也不会丢。不想调的话什么都不用管——默认值都取各自范围的中点。

面板底部有一条**速度响应曲线**：横轴 `t`、纵轴 `v`，把"起步加速 → 峰值 → 收尾停下"画成
一条线，**随 5 个参数实时变化**。5 个参数**各自占一段、各有一色**（与对应滑杆同色，
颜色深浅跟着该参数的档位走），所以"哪段是哪个参数在管"一眼就能对上。它是**直观示意**，
不是逐点复刻公式——用来判断拖杆的方向和幅度，不是用来读数。

<p align="center">
  <img src="test/settings.png" alt="Smooth Wheel Scroll 设置面板" width="330">
</p>

想确认它加载了：看扩展列表或 REAPER 启动日志，插件名会显示为
`Smooth Wheel Scroll 1.6.0`。

### 卸载

删掉 DLL，重启 REAPER。除面板参数外不写任何配置，删掉即干净。

## 从源码构建

全部代码就是一个翻译单元加一个头文件，用 C++ 编译器对着 REAPER 扩展 SDK（已随仓库
附带在 `third_party/`）编译。

需要：Windows x64 的 C++17 编译器。参考构建用的是便携版 MinGW-w64（g++）。

```sh
./build.sh                 # 产出 release DLL -> build/reaper_smoothwheelscroll-x64.dll
./deploy.sh                # 可选：复制进便携版 REAPER 的 UserPlugins
```

可选构建参数：

| 参数 | 作用 |
|---|---|
| *（无）* | 默认构建，**含**设置面板 |
| `--no-settings-ui` | 不编译设置面板（无面板、无菜单项、无动作的最小 DLL） |
| `--debug-log` | 额外编译诊断日志（写入 `%TEMP%\SmoothWheelScroll.log`） |

`deploy.sh` 在 REAPER 已加载该 DLL 时会拒绝执行；它读取环境变量 `REAPER_DIR`
（默认 `/d/REAPER`）。

### 验证动画模型

动画是**纯数学**，不依赖 REAPER、不依赖 Windows，放在 `src/anim_core.h`。可以脱离宿主
单独跑：

```sh
./test/check_curve_model.sh   # 曲线模型：单格行程 / 单峰 / 封顶 / 连滚累积 / 与步长无关
./test/check_classify.sh      # 分类规则：改动前后逐条对比
```

`check_curve_model.sh` 要求**单格行程 1.89**（已验收的参考值），并要求速度曲线在
各种参数组合下都是**单峰**、长滚**不越过** Hold 定的上限。

| `versions/<ver>/` | 冻结快照（源码 + DLL + `MODEL.md`） |
| `third_party/` | REAPER 扩展 SDK |
| `_diag/` | 开发期用的只读测量探针 |

### 动画模型

速度是一条曲线：**起步升上来 → 到峰值 → 收尾降回 0**；位置是速度的积分，所以曲线什么样、
运动就什么样。曲线由 5 段拼成，每段由一个参数（滑杆）和它对应的**旋钮**控制：

| 参数 | 管什么 |
|---|---|
| **Start** | 第一段的扬升；它的**旋钮**是起步时长（20–150 ms） |
| **Accel** | 第二段（爬到顶）的扬升；旋钮调该段的曲率 |
| **Hold** | 爬升的后段——**也决定速度上限**；旋钮调该段的曲率 |
| **Coast** | 到顶之后的下冲 |
| **Release** | 收尾的时长（20–300 ms） |

* 每格滚轮给一个**速度冲量**，连滚会叠加，于是"越滚越有劲"，直到 **Hold 定的上限**封住。
* 各段用**圆弧**从自己的两端之间鼓起来，**垂直于该段在屏幕上的走向**（不是垂直于数字空间——
  面板的横纵比例不同，两者会差几十度）。
* 段与段之间用**倒角**（取每段长度的 2/5）圆滑过渡；倒角随两端在屏幕上的实际长度变化，
  所以线越长、圆角越从容。
* 曲率有上限：**任何一条线无论怎么鼓，都不会越过水平**——上坡段不会先往下掉，
  下坡段不会翘起来。
* 运动积分在固定小步长网格上，所以**与计时器频率无关**。

**关于"冻结"**：**1.5.x 的物理模型是上一代**，完整归档在 `_hist/MODEL_1.0/`。
**1.6.0 是模型**（曲线），它在 1.5.3 的"显式速度封顶"之上继续演进：
把整条曲线改成**五段 + 倒角**、修好鼓包方向（按屏幕空间取垂直）、加上曲率上限。
此时起 `test/check_v1_baseline.sh` 针对的是**旧的物理模型**，已不再适用于当前模型；
当前模型的门是 `test/check_curve_model.sh`（单格 **1.89**）。

### 投递

动画算出的行程，用 REAPER 自己的**相对编码**交给动作（整数 7 位部分 + `1/256` 小数部分，
即最小步进 `1/3840` 格）。而且是**分小份、按时间**送，而不是几个大整数——这正是慢速时
顺滑的来源。

有两处**有界例外**，都是实测后定的，不要据此推广：

* **MIDI 编辑器竖直轴**（滚动与缩放）：接收方按整行/固定 2px 步进量，`1/3840` 格无法表达，
  所以给"接收方表达得出的最细步进"。
* **调音台横向滚动**：无动作可重放，改为把行程作为**小滚轮消息**交给 REAPER 的调音台窗口，
  由 REAPER 自己的 `Scroll MCP` 规则决定步长。

### 参数传达原则：不考虑接收方的限制

**这条是本项目的根本原则，写死在这里，任何改动都要遵守：**

> 插件只负责**把参数传达做到极致**——用尽可能高的精度、把模型做得尽可能优雅。
> **不考虑接收方（REAPER）自身的能力上限或限制。**
> 接收方能不能处理、处理得好不好，**是接收方的事**；它处理不了，它自己会去优化。

具体地：

* **精度一律给足**：相对值用 REAPER 自己的相对编码，带上 `1/256` 的小数部分，最细步进
  到 `1/3840` 格，不退化成只发整数。
* **动画算出多少就传多少**，小数照送。
* **不因"接收方可能处理不了"而降低精度**，也不因"接收方会踩到限制"而给模型或投递加
  人为下限（例如"最小 N 像素""至少 1 单位才发"这类地板）。
* **不替接收方做取舍**：不预判某条动作"吃不了这么多"就把它排除——该绑的绑定，该怎么传就
  怎么传。
* 遇到接收方处理不佳，**不视为插件的缺陷**，也不通过降低插件品质去"修复"它。

插件只对"参数传达"这一件事负责，并把它做到最好。

### 动画时钟

采样密度和数值精度同样重要。测试机上 `SetTimer` 与 `CreateTimerQueueTimer` 无论请求
多小都被钳在 ~15.6 ms，采样点太少。所以插件用**多媒体计时器**（`timeSetEvent`）跑 1 ms。
它的回调在计时器线程上，而 REAPER 必须在主线程调用，因此回调只向插件自己的一个消息窗口
`PostMessage`，由 UI 线程执行实际工作。

## 设计说明

有些结论是**实测**定的，不是偏好。记在这里，免得以后重新推一遍。

* **参数控件永不进黑名单。** 实测确认：滚轮下的改值要么以**非 `View` 动作**的形式出现
  （MIDI 力度是动作 `999`），要么**根本不产生动作**、在窗口内部改值（偏好设置的下拉框
  实测从一项跳到下一项）。两类因此天然安全：规则"不是 View 滚动/缩放就不插手"已经覆盖它们。
* **同一个窗口可以既是视图又是参数。** MIDI 音符区里，普通滚轮是视图缩放，`Alt`+滚轮是
  改选中音符的力度——**窗口类完全相同**。只有 REAPER 报出的动作能区分二者。所以判据必须是
  **动作**，不能是窗口。
* **列表做过、测过、撤掉了。** 列表按整行移动，且原生响应已是瞬时，平滑到达只能加延迟。
  该实验归档在 `versions/1.4.0/`（**不属于发布内容**），连测量数据一起保留。
* **面板的浅色/深色是"两套固定配色 + 一个开关"，不是逐点推导。** REAPER 的暗色机制还没成熟
  （`GetSysColor` 在暗色下**返回值不变**，实测），所以插件只问一件事——REAPER 自己的
  `win32_darkmode`——来决定用哪套；颜色则各用各自可靠的来源（深色读主题、浅色用标准系统色）。
  切换靠**轮询**兜底，因为 REAPER 不保证为这个切换发通告。

## 适用范围与限制

* **只做 Windows x64。** 插件挂的是 Win32 窗口消息；macOS / Linux 需要各自的窗口钩子实现。
* **只针对普通有格鼠标。** 触控板、触摸、高分辨率滚轮交给 REAPER——它们本来就是细粒度，
  插件的意义正是让有格滚轮也给出同样细腻的信号。
* **设置面板。** 面板里有缓动总开关、5 个滑杆，以及每个滑杆对应的**一个旋钮**。
  * 滑杆调**手感形状**：起步力度、加速堆量、缓动时长、**速度上限（Hold）**、下冲（Coast）。
  * 旋钮调**细节**：Start 的起步时长（20–150 ms）、其余四段各自的曲率。
  * 每个滑杆和旋钮的**默认值都取各自范围的中点**；改动即时生效、自动保存。
  * 面板**跟随 REAPER 的浅色/深色**：标题栏、面板底色、文字、滚动条都会跟着切，
    切换后**不需要重开窗口**。推子、旋钮和曲线**保留自己的配色**（两套明暗下都好看）。
  * 开关条本身也**可以点**：关掉即完全放行，滚轮回到 REAPER 原生行为。
* 插件**不会**在本身已带惯性的驱动之上再叠一层；如果你的设备已经有平滑，可能会感到双重缓动。
