# SmoothWheelScroll for REAPER 1.4.0

**本版新增：列表控件（`SysListView32` / `SysTreeView32`）缓动。**
范围：视图滚动 / 视图缩放（1.3.0）**+ 标准列表控件**。

## 1.3.0 的否定结论有一处是错的（必须更正）

1.3.0 判定"列表不做"，给了三条理由。本次**重新实测**，其中第 2 条**不成立**：

| 1.3.0 的说法 | 本次实测 |
|---|---|
| ① 虚拟化列表，最小单位是一整项 → 只能一跳一跳 | **成立**（见下"能到什么程度"） |
| ② 重放 `WM_MOUSEWHEEL` 对它们无效（`nPos` 0 → 0） | **不成立**。干净测量：一格 120 → **+3 行**。旧的 0→0 是读数方法的问题（没等滚动动画停下就读、或没把光标停在控件上） |
| ③ REAPER 没有列表滚动接口 | 成立（动作路径确实够不着，所以必须走控件自己的窗口） |

②被推翻，所以"接不上"的结论不再成立——**列表可以接，走控件自己的 `WM_MOUSEWHEEL`，不经过 REAPER 动作，也就不碰 REAPER 任何状态**（符合铁律第四节/第六条）。

## 能到什么程度（诚实说明）

列表是**整项粒度**：一行就是一整行，永远无法在行内插值。所以"丝滑"的**上限**就是：

- **原生**：一格 120 → 3 行，**一次性**跳过去。
- **本插件**：同样 3 行，但按动画曲线**分摊到约 150 ms** 内陆续到达。

实测单格投递共 11 条消息（`11,8,13,17,18,19,17,14,6,3,1` 之类的形状），间隔约 **16 ms**。
即：**行的数量和原生完全一致，只是到达方式从"一步到位"变成"分散落下"**。这是"不那么突兀"，不是"触控板级丝滑"——那在整项粒度的控件上物理上做不到。1.3.0 的①说的就是这个，它仍然成立。

## 距离标定（为什么不能直接用模型的原值）

模型单格的行程是**原生的一小部分**（实测：**0.120 个原生格**，约 14 delta），这是用户认可的"轻盈起步"手感。
但列表**要 40 delta 才动一行**。所以模型的原始行程喂给列表 = 几乎不动——第一次实现正是这个结果（列表纹丝不动）。

因此列表**把距离钉死在原生**，只用模型决定**时序**：

- `ListGain()` 在加载时用模型自算——跑一格完整动画取总量，缩放到"一格 = 一个原生格（120 delta = 3 行）"。
  不写死任何数，跟随设置窗口的 Start / Release。
- **列表的加速度置 0**（`ListParams()`）：原生列表是**恒定 3 行/格**，模型那条"越滚越有劲"的加速度会让距离跑偏原生。

**实测距离**（`_diag/rolltest.exe`）：

| 滚轮 | 插件 | 原生 | 偏差 |
|---|---|---|---|
| 1 格 | 3 行 | 3 | **0 %** |
| 3 格 | 9 行 | 9 | **0 %** |
| 5 格 | 18 行 | 15 | +20 % |
| 10 格 | 36 行 | 30 | +20 % |

**长滚筒仍会超原生约 20%**——这是模型跨格累积的惯性（视图上也是这个特性，用户认可）。若要**逐格都对等**，需要把跨格累积也去掉；本次按"不要逐一适配得太细"未做，留作后续选项。

## 判定规则（刻意只有两个类名）

`ListWindow()` 只认两件事，没有逐控件表：

1. 类名 ∈ {`SysListView32`, `SysTreeView32`}（标准公共控件，REAPER 的工具窗口都建在这上面）；
2. **真的能竖向滚动**：`GetScrollInfo(SB_VERT)` 要求 `nMax > 0 && nPage > 0` 且 `nMax-nPage+1 > 0`。

第 2 条是必要的：媒体浏览器的树 `nMax=0, nPage=0` 却报出假的区间 1，被它挡掉（实测：该控件原生滚轮就是不动 `+0`）。**不写死任何窗口标题 / 控件名 / 矩形**，REAPER 以后新增或改名列表自动生效。

**被排除的（这是关键）：**

- `ComboBox` **下拉框**（`ComboLBox` / `ListBox`）是**选择器**：滚一格会**改值**。实测偏好设置里的下拉框，真滚轮一格 `sel 0 → 1`。已实测下**不接管**。
- 面板：`REAPERTCPDisplay` / `MIDIPianoWindow` 走**动作**（1.3.0 已做），不经此路径。
- 3.0 的假阳性来源（不可滚动列表）已由第 2 条挡掉。

## 不改参数精度的验证（用户的两个前置条件）

| 前置条件 | 实测 |
|---|---|
| 列表能直接转 | ✅ 1/3 格距离与原生一致 |
| 不影响参数精细逐格更改 | ✅ 见下 |

- **MIDI 力度**（Alt+滚轮，动作 999）：插件加载 + 接管模式开，力度 `96 → 97 → 98`，**每格恰好 +1**，插件日志 `pass through cmd=999`。
- **偏好设置下拉框**（无动作、窗口内改值）：插件接管模式开，`sel 0 → 1`，**恰好一格**。
- **`#32770` 对话框从未被接管**：全日志中无一条 `surface != null` 的对话框滚轮。

## 模型（未改，仍为 1.1.0 定稿模型）

- 冲量 `v_k = dir·unit·(Start%+(k-1)Accel%)·Q/T`
- **每格独立**平滑渐入 `S(u)=3u²-2u³`
- 幂律摩擦 `dv/dt = -c·v^p`，p=0.8，`c` 由第一格标定
- 刹车随节奏放松 `relax = clamp(tempoRefMs/gap, 1, relaxMax)`
- 固定 0.25 ms 积分网格，与计时器无关

`anim_core.h` 与 1.3.0 **逐字节相同**（`diff` 为空）。列表只是**多了一个 drive**，模型本身一格没动。

| 参数 | 值 |
|---|---|
| Start | 15 % |
| Accel | 3.5 % |
| Release | 150 ms（同时 = 渐起窗口） |
| frictionPow | 0.8 |
| movingOnsetMs | 30 |
| tempoRefMs / relaxMax | 120 / 4 |

**对拍**（`test/check_v1_baseline.sh`）：单格 1.89，与 1.0.0 逐位一致。
（长滚筒的 -6.62/-7.41 漂移是 1.1.0 的**有意**改动——每格独立渐入，非本版引入。）

## 新增/改动的代码位置

- `enum Drive` 增加 `DRIVE_LIST`；`Integrator` 增加 `listHwnd`（并作为操作身份）。
- `OneNotchUnit(Drive)`：列表返回 `ListGain()`。
- `ListParams()` / `ParamsFor(Drive)`：列表的 `accelPct = 0`。
- `ListWindow()` / `ClassIsList()` / `ListCanScrollV()`：表面判定。
- `DeliverTravel()` 的 `DRIVE_LIST` 分支：累积整数 delta，`SendMessageA(listHwnd, WM_MOUSEWHEEL, ...)`。
- `ApplyTravelNow()` 的 `DRIVE_LIST` 分支（Release 极短时的同步路径）。
- `GetMsgProc()`：先查列表，再查面板。
