# SmoothWheelScroll for REAPER 1.4.1

**本版新增：轨道面板两侧的"分割线"（宽度拖拽条）接上滚轮。**
范围：视图滚动 / 视图缩放（1.3.0，未变）**+ 这两条分割条**。
（1.4.0 的"列表缓动"已在 `versions/1.4.0/` 归档为**未采纳**，本版未包含。）

## 问题

轨道面板左右各有一条窄条，是用来拖拽面板宽度的。滚轮停在上面时：

- **外侧一半**：REAPER 原生就发 `990 View: Zoom horizontally`（和主视图一样）→ 插件早就在缓动它。
- **内侧一半**：**原生什么都不做** → 这就是 1.3.0 缺的那块。

用户对语义的说明（本版据此实现）：

> 靠轨道一边的是轨道滚动，外侧的就是跟主视图一样，水平缩放，就好像这个轨道面板装在主视图里一样，它的边缘外面就是主视图。

## 实测（逐像素，`_diag/scan_strips.cpp` + `input_probe.exe`）

某个布局下 TCP 为 `1287,685,1790,1973`、arrange 从 `1798` 起、左侧邻居是混音台：

| 条 | 靠面板侧（内半） | 外侧半 |
|---|---|---|
| 左 `1280..1286` | `1284..1286`：**原生无动作** | `1280..1283`：原生 **990** |
| 右 `1790..1797` | `1790..1794`：**原生无动作** | `1795..1797`：原生 **990** |

两条条**方向相反**（左条的邻居是混音台、右条是主视图），所以必须按几何分别识别，不能用一个常数。

## 实现

- `TcpDividerIsInner()`：从面板边缘向外 `WindowFromPoint` 走到第一个**非 chrome** 的窗口，得到条的宽度；只认**内半**。
  "chrome" 定义为 `REAPERwnd` / `#32770` / `Static`（主窗口自绘的裸边 + 混音台外框 + 静态文本）。
- 内半 → 返回 TCP 窗口 → 走**已有的 989**（竖直轨道滚动），与面板本体完全同一条路径。**不新增任何驱动**。
- **外半完全不碰**（`return nullptr`）→ 主视图自己的映射（含所有修饰键）原样保留。
- 一半的取法：`n = 宽度 / 2`（**向下取整，至少 1 像素**）。向下取整是安全方向——多认一个像素会**丢掉**一个原本能做水平缩放的像素；少认一个只是那一像素维持原样（原本也不响应）。
- **只有窄条才算**（`宽度 <= 16`，`_diag/scan_strips.cpp` 实测条宽 2–8）：面板贴边、旁边没有混音台时那大片裸边不会被误认。

## 验证（真机，release DLL）

按位置读**插件实际 kick 的动作**：

| x | 区域 | kick | 语义 |
|---|---|---|---|
| 1284–1286 | 左内半 | **989** | 轨道滚动 ✅ |
| 1500 | TCP 本体（对照） | 989 | 轨道滚动 |
| 1280–1283 | 左外半 | **990** | 水平缩放 ✅ |
| 1790–1793 | 右内半 | **989** | 轨道滚动 ✅ |
| 1795–1797 | 右外半 | **990** | 水平缩放 ✅ |
| 1798+ | arrange（对照） | 990 | 水平缩放 |

即：**内半与面板本体同动作，外半与 arrange 同动作**——正是要求的分工。**没有任何一个原本发 990 的像素被夺走**（`1794` 保持原生无动作）。

另有像素级动效验证（`_diag/visual.cpp`，只 BitBlt 读屏）：内侧条→面板区域变化；外侧条→主视图区域变化。
