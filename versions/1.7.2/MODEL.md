## 1. 修复：调音台的推子 / 旋钮被误接管

**报告**（用户 **Daodan** 发现，本机复现确认）：在调音台里滚**推子 / 旋钮**，一下加了 **+12 dB**，
而原生是 **+3 dB**。

### 根因

调音台那条分支（把手势交给 MCP 窗口）**无条件接管** —— 它的注释自己就写着
*"The wheel is taken UNCONDITIONALLY here."*：只要光标落在混音台范围内，**不管那里是不是参数控件**，
都会把原消息吞掉（`WM_NULL`）再由插件重发。

而**推子是"按每条 wheel 消息"步进的**（一条消息 = 一跳，与传进去的值大小无关），
插件送出的却是一**串**整格 delta（动画每帧累加、跨阈值就发一条）→ **一跳变多跳**，+3 变成 +12。

这与项目里已记录过的两类失效**同源**：`one page`（一格被放大成 28 次翻页，§19.8）、
MIDI 竖直缩放（固定 2px 刻度被拆成碎步，§17）。**这类问题的正解永远是"别碰它"，不是调步长。**

### 修法（最小改动：1 个文件、16 行）

在该分支上加一道闸：把 `GetThingFromPoint` 的命中串过一遍 **`ThingIsValueControl()`**，
**命中就放行**给 REAPER；只有混音台**本体 / 空白处**才继续走原来的滚动逻辑。

`mcp.volume` / `mcp.pan` / `mcp.width` / `mcp.recinput` / `mcp.recmode` / `mcp.fxparm` … 这些名字
**本来就在** `ThingIsValueControl` 的名单里 —— 只是这条分支**从来没调用过它**。

### 混音台滚动未受影响

用户此前验收过的混音台**横向滚动**手感（"优雅，完美了"）**不在本次改动范围内**：
闸门只拦**参数控件**，本体与空白处照旧。

## 2. 未改动

- **模型**：上表 7 个头 / 源与 `v1.7.1` **逐字节相同** → **不需要同步 Apex**。
- **投递层 / 设置面板 / 动作表 / 分类规则**：一行未动。
- **竖直缩放**：**本版没有改它**。本节顺带记一次核实（详见 `AGENTS.md` §111之补（二））：
  把该轴的投递粒度从"整单位"降到 **1 delta** 实测**更差**（更不线性、整体更不舒服），
  故维持整单位。**"换模型"（§111）与"改步长"（本次）两条路都已用实测走完。**
