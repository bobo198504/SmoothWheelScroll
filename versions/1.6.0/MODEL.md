**模型结构有改动**，因此是新版本，不是 1.5.3 的补丁。

## 1. 模型：物理 → 曲线

**1.5.x 及更早**是**物理模型**（速度冲量 + 幂律摩擦 `p=0.8` + 惯量累积）。
它已**完整归档**在 `_hist/MODEL_1.0/`（含当时的门与对拍脚本），作为手感历史保留。

**1.6.0 是新模型**：速度是一条**曲线**，位置是它的积分。曲线由 **5 段**拼成：

| 段 | 由谁控制 | 说明 |
|---|---|---|
| Start | 滑杆 + 旋钮 | 滑杆管第一段扬升；旋钮是**起步时长**（20–150 ms） |
| Accel | 滑杆 + 旋钮 | 爬到顶那一段；旋钮调曲率 |
| Hold | 滑杆 + 旋钮 | 爬升后段，**同时决定速度上限**；旋钮调曲率 |
| Coast | 滑杆 + 旋钮 | 到顶后的下冲；旋钮调曲率 |
| Release | 滑杆 + 旋钮 | 收尾时长（20–300 ms）；旋钮调曲率 |

关键性质（都在 `test/check_curve_model.sh` 里守）：

- **单峰**：任何参数组合下速度只有一个峰值（这正是换掉物理模型的原因——它会双峰）。
- **封顶成立**：长滚的峰值永不超过 Hold 定的上限。
- **连滚累积**：滚得越长越快。
- **与步长无关**：固定小步长网格积分，不随计时器频率变化。
- **单格行程 1.89**（已验收基准）。

### 1.1 鼓包方向（修掉一个一直存在的错误）

每段是一条**圆弧**从自己的两端之间鼓起来。原来"垂直"是在**原始数字空间**里算的，
但面板的横纵比例不同（实测 1 个 x 单位 ≈ 308px、1 个 y 单位 ≈ 106px，纵向被压约 2.9 倍），
于是"数字里的垂直"画出来**不垂直**：实测某段**画面 32.6°** 的弦，鼓包却朝**画面 135°**（差 13°）；
更早按原始数字构造的那版差 **43°**（几乎竖着往上鼓）。

现在按**绘制空间**取垂直：给形状一个 `ax` 因子（一个 y 单位值多少个 x 单位），
在"x 按 y 计价"的空间里构造圆弧再换算回来。`ax = 1` 精确退回旧行为，所以模型那侧不变。
**实测：三个有鼓包的段，修后偏差 0.00°。**

### 1.2 曲率上限：不许越过水平

圆弧的**端部切线**相对弦偏摆 ±α（`α = asin((L/2)/R)`，弧的半张角）。
于是"不许越水平"等价于 **`α ≤ |弦角|`**，有闭式解：

```
sagitta ≤ r / (2(√(r²+1) + 1))      r = 弦在测量空间里的陡度
```

它与原有的"不折叠"上限取更紧的那个（两者在 45° 弦相等；更陡的由折叠限、更缓的由水平限）。
**旋钮 = 上限的完成度**，且满旋钮只用到上限的 **50%**（`kCurveMaxFrac`），
所以任何旋钮拉到底都**不会**让上坡段先往下掉、或让下坡段翘起来。
**实测 132,000 个切线采样点，越界 0 个。**

### 1.3 倒角

段与段之间用**倒角**圆滑过渡，取每段长度的 **2/5**（`kFilletFrac = 0.40`）。
倒角尺寸**来自它连接的两段在屏幕上的长度**，所以线越长、圆角越从容。
实测最紧处半径：1/5 时 0.81px → 2/5 时 1.70px。

> ⚠️ **不要重试 C2（五次 Hermite）桥。** 试过一次：为了让肩部曲率连续，丢掉三次桥上的
> **"Y 单调钳位"**，结果在 `bend=+0.5` 时产生**真实双峰**，门从 9/9 掉到 6/9。
> 已完整回退。**"更平滑"的几何直觉可能违反单峰这个结构约束。**

## 2. 设置面板：旋钮、默认值、明暗跟随

### 2.1 每个滑杆配一个旋钮

5 个滑杆调"形状"，5 个旋钮调"细节"（Start 的起步时长 + 其余四段的曲率）。
**所有滑杆与旋钮的默认值都取各自范围的中点**：Start 20–150 ms（默认 85）、
Hold 旋钮 1.25–2（默认 1.625）、Accel/Coast/Release 旋钮 −0.5..+0.5（默认 0）。

⚠️ **Hold 旋钮下限是 1.25 而不是 1.0**：1.0 时那一段是**完全直线**，看起来像"旋钮没作用"；
1.25 起仍有可辨的鼓起（实测段中点偏离弦 1.50px）。

### 2.2 面板跟随 REAPER 的浅色/深色

**两套手工调好的固定配色，用一个开关选**（`win32_darkmode`）：

- 开关经 `get_config_var` 读，失败则读 `reaper.ini`（**实测本机只有后者能读到**）；
  两者都只读，不写 REAPER 任何文件。
- **深色**用**主题自己的颜色**（`GetThemeColor` + `ColorFromNative`），所以与用户主题一致；
  **浅色**用**标准系统色**（`GetSysColor`）。两套各自可靠。
- **标题栏**用同一开关驱动（`DwmSetWindowAttribute`，双向），
  另设 `DWMWA_BORDER_COLOR` 让窗口边框与面板一致。
- **滚动条**（非客户区、系统绘制）通过 `DarkMode_Explorer` 窗口主题跟随。
  > ⚠️ 这条**未在本机验证出效果**（逐点读屏在 DWM 下不可靠），是"按官方手段实现、待确认"。
- **切换靠轮询兜底**：REAPER 不保证为这个切换发 `WM_THEMECHANGED`（实测浅→深会发、深→浅不发），
  所以定时器里读一次开关，变了才全量刷新。

### 2.3 配色引擎已删除（重要）

1.5.3 那套"读主题 + 按亮度推导一套配色"的引擎**整个删除**，连同强制暗色的
`ApplyTitleBar`/`SetWindowTheme` 调用、`get_config_var`/`ColorFromNative` 之外的引入。

**原因（实测）**：`GetSysColor` **不跟随暗色**——进入暗色模式前后 `COLOR_3DFACE` 都是 `F0F0F0`。
所以"用标准系统颜色"在深色下必然失败，现象就是**复选框变暗了、面板没变**（取色源分裂）。

**教训**：**能交给标准机制的就不要自己实现**；自建"猜测 + 兜底"体系本身就是 bug 来源。

## 3. 本版修掉的三个真 bug

| bug | 根因 | 现象 |
|---|---|---|
| **Hold 滑杆超过一半无反应** | 塑形代码里 `if (hold > 1.0) hold = 1.0;` 是滑杆还是 0..1 时的钳位，滑杆放宽到 2 之后忘了改 | 线的角度在 hold 1.0/1.5/2.0 上**逐位相同** |
| **旋钮值被写坏** | `RefreshDerived` 用**同一把** `[-0.5,0.5]` 钳位钳所有旋钮，而 Start 是 20..150、Hold 是 1.25..2 | 每次载入/刷新，Start 被钳成 0.5、Hold 被钳成 0.5 |
| **总开关点不动** | 复选框改成自绘（`BS_OWNERDRAW`）后，`BM_SETCHECK` **对它无效**（实测设置后 `BM_GETCHECK` 仍是未勾选） | 功能正常（`g_glideOn` 在翻转），但勾**画不出来** |

三者的修法分别是：钳位跟着滑杆自己的最大值；**每个旋钮用自己范围**的单一来源表；
状态**只放在变量**里（`g_glideOn`），读写都不再依赖控件状态位。
