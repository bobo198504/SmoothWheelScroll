## 1. 八个速度旋钮

**来源**：论坛用户 **graysonsolis** 提出 —— "even at quickest settings the vertical scroll still
feels very sluggish"，希望**主视图和 MIDI 编辑器的滚动/缩放能各自调**。

面板在四个滑杆下方多一条旋钮带，**一个旋钮对应一个"视图 + 方向 + 平移/缩放"**：

| 旋钮 | 动作 |
|---|---|
| Main scroll vertically | 989 / 978 |
| Main scroll horizontally | 988 / 977 |
| Main zoom vertically | 1000 / 1001 |
| Main zoom horizontally | 990 / 979 |
| MIDI scroll horizontally | 40433 / 40660 |
| MIDI zoom vertically | 40430 / 40663 |
| MIDI zoom horizontally | 40431 / 40662 |
| Scroll MCP | `DRIVE_MCP_WHEEL`（调音台）|

**范围 0.5x ~ 3.0x，默认 1.0x。** 每个旋钮**即时保存**，**双击复位**到 1.00x。

### 系数乘在哪里

**乘在"行程"上，在模型之前**：

```
滚轮 → 基础行程 → ×系数 → 模型（窗口 / 161）→ 投递（网格 / 补发 / 宏）
```

**这样**：滑行形状不变（只是距离变了）；**行高补偿、两个投递网格、手势末端补发、宏 ——
全部照常**；**1.0x 时逐位不变**（默认就是 1.7.6 的行为）。

### 旋钮位置是对数的（关键决定）

**用户要"最大 3x"和"默认值在正中间"同时成立。**

**线性做不到**：0.5~3.0 线性时 1.0 落在 20% 处，不是中间（线性中点是 1.75）。

**做法：指针位置走【分段对数】** ——

| 指针位置 | 倍数 |
|---|---|
| 0（最左）| **0.5x** |
| 250 | 0.707x |
| **500（正上方）** | **1.00x** ← 默认 |
| 750 | 1.732x |
| 1000（最右）| **3.0x** |

左半圈按 `0.5 → 1.0` 对数分布，右半圈按 `1.0 → 3.0` 对数分布，**各占一半行程**。
值本身仍是普通倍数，只有"位置 ↔ 值"的映射是非线性的。
**往返精确**（实测每个位置转回来不变）。

### 存储

键名 `sspd0` ~ `sspd7`，按 `Surface` 枚举顺序。

**★ 前缀 `sspd` 是版本号，不是手误**：枚举少了一个成员（见第 3 节），索引 4 之后整体前移，
**沿用旧键 `spd4..` 会让一个视图的设置跑到另一个视图上**。换前缀后旧键不再读、并顺手清空，
所有旋钮从 1.0x 开始。

## 2. ★ `anim161_core.h` 不再丢弃喂入的行程

**主视图垂直缩放走的是 1.6.1 曲线模型**（`FullTravelFor` 选中）。它的 `Kick()` 里有：

```cpp
(void)unitTravel;      // 行程被丢弃
```

**所以旋钮对这条轴完全无效** —— 模型用自己的 `claimBase` 算距离，不看调用方给什么。

**改法**：`unitTravel` 相对**标定的一格（15 单位）**的比例，乘到 `claim` 上：

```cpp
const double kCalibratedNotch = 15.0;
if (unitTravel > 0.0)
  claim *= (unitTravel / kCalibratedNotch);
```

**锚定常量而不是 `Params` 字段**：标定属于模型，一个能从外部改的值会悄悄重定义"一格"。

**验证（实测）**：

| 传入 | 输出 | 倍数 |
|---|---|---|
| **15** | **2.283063** | **1.0000** ← **与 1.6.1 原来的值逐位相同** |
| 7.5 | 1.14153 | 0.5000 |
| 30 | 4.56613 | 2.0000 |
| 45 | 6.84919 | 3.0000 |

→ **1.0x 时手感一个数都不变**，这是它在模型头里安全的最小理由。

## 3. ★ MIDI 垂直滚动【故意没有旋钮】

**这是实测结论，不是漏做。**

该轴走 `kStepUnits`（整 7-bit 单位网格）。**系数放大的是行程，不是发送次数** ——
每一帧的位移被攒成整单位再一次性发，所以**放大 = 每次发得更大，而不是发得更快**。

**实测**（DEV 日志，`cmd=40432`，旋钮 3.00x）：

```
kick ... surf=4 mul=3.00 units=1.00 amount=-26.2957 ...
replay sec=32060 cmd=40432 val=121 valhw=-1     ← 7 个单位一次性发出
replay sec=32060 cmd=40432 val=114 valhw=-1     ← 14 个单位一次性发出
replay sec=32060 cmd=40432 val=1   valhw=-1     ← +1
```

（`val` 是 7-bit 二进制补码：121 = −7，114 = −14。）

**`amount` 从约 8 单位/格涨到 26**，但发出去的是**一次 7~14 个整单位**，≈半行音高。
REAPER 的 MIDI 垂直滚动按**音高行量化**（AGENTS §17），所以它确实走得更远了，
**但步子更粗、不是更快** —— 用户的实际感受就是"旋钮没反应"。

**一个做不到标签承诺的旋钮，比没有旋钮更糟**，所以这条轴不提供，保持在 1.0x。

**代码上钉死**：`routing.h` 的 `SurfaceIsAdjustable()` 对
`(section == MIDI && axis == vertical && kind == scroll)` 返回 false，
`SurfaceSpeedFor()` 直接给 1.0。**旋钮表说"用户能转什么"，这个函数说"投递实际干什么"** ——
两者不能漂移，所以后者是唯一的裁决点。

**要真正变快需要更细的投递**，而 AGENTS §17 已实测细分会造成顿挫（按行量化 + 每次独立取整）。
**不要随手重试。**

## 4. 面板布局

- 旋钮带在四个滑杆下方、运动图上方。
- 旋钮风格照 1.6.1：**小方盘（直径 = 行高）+ 旁边的静态标签**，不在控件内画字。
- 标签用 **REAPER 自己的动作名**（去掉 `View: ` 前缀），前面加视图名：
  `Main scroll vertically 1.00x`、`MIDI zoom horizontally 1.00x`、`Scroll MCP 1.00x`。
- **间距 15px**，**排不下自动换行**（按面板宽度计算每行几个）。
- 指针从接近圆心画到边缘、**2px 粗**：小尺寸下"圆心到边缘的一条细线"看不出方向。
- 面旋钮的配色**单独给**（`SliderColor`）：它们没有对应的滑杆行，
  原来会落进兜底分支返回 `g_theme.text`，**指针和圆盘同色 → 指针消失**。
