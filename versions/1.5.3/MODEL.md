## 1. 修复：设置面板崩溃 —— `SetWindowTheme` 递归风暴

**两位用户反馈**（1.3.9 发布版）：打开设置面板即崩溃，Windows 10 / 175% DPI。

**根因（已复现）**：`SetWindowTheme()` 会**发送** `WM_THEMECHANGED`，而处理函数里又调了
`ApplyWindowTheme()`（内含 `SetWindowTheme`）→ 自我触发，实测每次调用重入 **31 层**
（Windows 的 `SendMessage` 重入上限）。每层还跑一遍主题解析 + 3 次 GDI 画笔删除/创建 +
重绘 + 遍历子窗口。窗口创建期的一次开面板 = 31 次主题重解析 + 近百次 GDI 对象增删。
**175% DPI 绘制更重，因此那两个用户命中率高。**

**修法（双重防护）**：

1. **重入守卫**：`WM_THEMECHANGED` / `WM_SYSCOLORCHANGE` 处理函数开头持有
   `static bool inThemeChange`，重入即返回 → **31 层降到 1 层**。
2. **"同主题不重发"记忆**：`ApplyWindowTheme` 记住上次对某 HWND 应用过的 `(hwnd, dark)`，
   相同则直接返回 → **从源头不发** `SetWindowTheme`。`ForgetWindowTheme()` 在 `WM_DESTROY` 清记忆。

**实测**：打开面板 → 修复前 `entries=31`、每层重建画笔；修复后 **`entries=1`**。

**教训**：`SetWindowTheme` 是**会回发消息**的 API，处理函数里绝不能再无条件调它；
这类 API **必须同时**做重入守卫**和**状态变化检测。

## 2. 新功能：主视图两条滚动条接上滚轮

滚动条**没有窗口类**（REAPER 用内部 CoolSB 自绘，`GetThingFromPoint` 也只返回 `arrange`），
所以只能**按几何**识别：贴 arrange 窗口内边缘、宽度取系统度量
`GetSystemMetrics(SM_CXVSCROLL/SM_CYHSCROLL)`（本机 17px，随 DPI 缩放），
再**向内缩 1px**（宁可少认，绝不偷走 arrange 的像素）。

> ⚠️ 宽度相等是**实测吻合**，不是 REAPER 的承诺——换主题/DPI 未验证，故取用时留了 1px 余地。

**映射（用户实测给的规则：带 Alt = 缩放类，不带 = 滚动类）**：

| 滚动条 | 不带 Alt | 带 Alt |
|---|---|---|
| 垂直 | **989** `View: Scroll vertically` | **1000** `View: Zoom vertically` |
| 水平 | **不接管**（放行；原生是"翻页式快移"，与连续缓动不是同一手势） | **990** `View: Zoom horizontally` |

全部只给**相对值**，缩放锚点/步进/范围仍归 REAPER。命中后**吞掉原消息**。

**验收**：用户实测"主视图滚动条没问题了！"。

## 3. 行为修正：轨道面板遵从 `Scroll TCP`

TCP 的滚轮滚动**不是动作**，而是**鼠标修饰键行为**
（`reaper-mouse.ini` 的 `MM_CTX_TCP_MOUSEWHEEL`，默认 = 内置 `Scroll TCP`）
——这正是它当年不进 `hookcommand2`、必须被拦截的原因。

现在改为**先读后判**：用官方 `GetMouseModifier(MM_CTX_TCP_MOUSEWHEEL, flag, ...)`
读出该组合当前绑的是什么，再决定是否接管：

```
"1 m" (内置 Scroll TCP)             -> 重放 989  View: Scroll vertically
"3 m" (内置 Adjust vertical zoom)   -> 重放 1000 View: Zoom vertically
其它（Passthrough "4 m" / 未分配 "0" / 自定义） -> 放行，插件不接管
```

→ **尊重用户的自定义**，而不是硬拦。`GetMouseModifier` 不可用（返回空串）时退回
"普通滚轮→989、Ctrl→1000"，避免静默失去面板滚动。

（内置鼠标修饰键 id 无官方文档，实测值记录在 AGENTS.md 19.19：`1 m`=Scroll TCP/MCP、
`3 m`=Adjust vertical zoom、`4 m`=Passthrough、`0`=未分配。**不要靠猜。**）

**验收**：用户实测"对的，TCP 和 MCP 都更健康了！"。

## 4. 新功能：调音台（MCP）横向滚动缓动

调音台**没有可重放的动作**（mixer 相关动作只有 `Toggle...`），其滚轮同样是鼠标修饰键行为
（`MM_CTX_MCP_MOUSEWHEEL` → `Scroll MCP`）。唯一官方接口是 **`SetMixerScroll(MediaTrack*)`**
——**收轨道指针，最小单位 = 一整轨**。所以新开一条投递路径：

- 新增 **`Drive::DRIVE_MIXER_SCROLL`**：`GetMixerScroll()` 取当前最左轨 →
  按**整轨**步进 → `SetMixerScroll(目标轨)`；余数**跨帧保留**（同 `kStepUnits` 思路），
  慢速时是"攒够一轨才跳"，而不是丢步。方向：wheel-up 露出更早的轨道（索引更小），故取负。
- 只在用户**仍是内置 `Scroll MCP`**（`"1 m"`）时驱动；`0`（未分配）或自定义 → 放行。
- **单位换算 `kMixerUnitsPerTrack = 1.89`**：目标是一格输入 = 一轨，使每格距离与原生一致、
  glide 只改时序。刻意用**命名常量、不从可调参数推导**——调 Start（视图手感）不应改变调音台速度。

**验收**：用户实测"TCP 和 MCP 都更健康了！"。`1.89` 若日后实测发现并非正好一轨，
它就是那个旋钮。

## 5. 新功能：设置面板的响应曲线

面板底部一块带 `v` / `t` 轴的绘图区，画"起步加速到停下来"的**速度示意线**，
随 5 个参数**实时**变化。

**它是示意图，不是模型采样。** 这一条是用户把方向纠正过来的：跑真实模型会让形状取决于
各机制恰好怎么互相作用，在某些设置下画出**双峰/压平**（Hold 拉小最明显）——
而那不是这 5 个控件要表达的东西。用户原话："模型应该没问题，是**画图逻辑**的问题。"
所以 **5 个滑杆各拥有一段**，谁大谁陡/谁长一眼可见。**不要改回跑模型。**

**分段与角度（用户逐条口述，别再自创）**：

| 段 | 参数 | 决定 | 角度范围 |
|---|---|---|---|
| 1 | Start | 第一段的扬升 | 10° – 60° |
| 2 | Accel | 第二段（到顶）的扬升 | 15° – 60°（不取 0） |
| 3 | Hold | 第二段**后半段压下来的幅度**（= 峰高） | 3° – 35°（不取 0） |
| 4 | Coast | 下滑前半段的**下冲**，并决定腾空长度 | — |
| 5 | Release | 收尾**时长** | 宽度 `0.20 + 0.28×relNorm` |

- 角度经 `tan` 转成**归一化绘图空间**里的斜率 → 画出的角度还取决于窗口宽高比。
  这正是用户说的"你可以转换成相对值，因为这个会随着窗口水平拉大而变化"。
- **Hold 同时拉长 Coast**：`wCoast = coast × (0.10 + 0.12×hold)`。
- **Coast→Release 接头连续**：`yCoastEnd = ySummit × (1 − min(coast×0.275, 0.55))`，
  所以 Coast 拉小时 Release 从**接近峰顶**处接上，没有悬崖。
- 拟合用**单调三次（Fritsch–Carlson）**：连接点一阶连续（不拐折）且不过冲（峰顶不冒头）。
- **按参数上色**：Start 蓝 / Accel 绿 / Hold 琥珀 / Coast 橙 / Release 紫；颜色 = 该滑杆
  **当前档位**的饱和度（从卡片底色混到纯色，系数 0.35..1.0）→ **只要不为 0 就永远看得见**
  自己的颜色。滑杆槽用同色低档、滑块用同色满档。
- **两轴动态**（按本次峰值/停稳时刻归一），但刻度标签取**真实值**（`CurveAnchors()` 跑一次
  10 格 @30ms 爆发的真实峰值与停稳时刻）→ **标签真值、形状示意**，这是刻意的组合。
- 曲线块高度 108 → **130**（+20%）。刻度 `NiceStep` 请求数 X=20 / Y=14（网格密、
  **标签逐个避让**）。刻度数字**更小更淡**（字缩放 0.68、下限 −8；色 `axisText`
  = 暗 `RGB(130,130,130)` / 亮 `RGB(150,150,150)`）；`v` / `t` 两个轴标注仍用较亮的 `sub`。

## 6. 模型：高速保持 = **显式速度封顶**（结构变更，已获用户批准）

**用户当场认可并选定**（原话"行，按 C 来"）。这是本版**唯一**动到 `anim_core.h` 的地方，
因此按项目铁律新建本版本快照，**不就地覆盖 1.3.9**。

**改前**：`Params::softStart` / `softPow` —— 一个软衰减 `1/(1+(v/knee)^pow)`。

**两个毛病**：

1. **它不是封顶**：永远还允许再加一点，所以"这拨能有多快"没有确定值。
2. **它让曲线双峰**：每格注入比上一格多（Accel），而衰减随速度上升注入更少；
   两者交叉处速度先掉再升 → 实测可见**第二个峰**（Hold 拉小时最明显）。

**改后**：`Params::speedCeiling` / `ceilingPow` —— 乘子 `1 − (v/ceiling)^pow`，
**在封顶处精确到 0**：速度可以逼近但永远不超过它。因子单调降到 0，**不可能出双峰**。

**hold 的几何斜坡 + 地板**（两端良定义）：

- `CeilingForHold(h)`：`h ≤ 1` 时 `250 × (1338/250)^h`，`h > 1` 时 `1338 × h`。
- `TempoRefForHold(h)`：`h ≤ 1` 时 `6 × (110/6)^h`，`h > 1` 时 `110 × h`。
- **低端是地板不是 0**：`tempoRefMs = 0` 会让模型把 `relax` 夹到下限，
  即"刹车全松"——那是**最大**效果而非最小，滑杆会不单调。`speedCeiling = 0` 同理
  （= 完全不限速）。地板还刻意高于普通滚动速度（实测峰值：单格 17、3 格@120ms 86、
  6 格@60ms 275），所以最轻的封顶也**不碰普通滚动**，只限真正快的。
- **`h = 1` 精确回到标定值**（1338 / 110）→ **默认手感不变**。

**实测（真实运行参数，10 格 @30ms）—— 单调**：

| hold | 0 | 0.25 | 0.5 | 1.0 | 1.5 | 2.0 |
|---|---|---|---|---|---|---|
| total | 54.53 | 68.10 | 79.30 | 335.60 | 429.53 | 449.07 |
| peak | 199.38 | 250.79 | 315.01 | 938.09 | 1113.42 | 1164.18 |

**单格**在 hold 0 / 1 / 2 下**逐位相同**（total 1.81、peak 11.95）→ 封顶对单格零影响。
