## 3. 三个手感机制（都是本轮新增，可关）

| 机制 | 参数 | 干什么 | 前期影响 |
|---|---|---|---|
| 高速收力（feed taper） | `softStart` / `softPow` | 速度越高，每格注入越少 → **无上限但增益递减**（"第一宇宙速度"） | 低于 knee 完全不生效 |
| 高速滑行（speed release） | `relGain` / `relRef` / `relFloor` | 速度越高，刹车越小 → 滑更远 | `relFloor` 死区保证**零影响** |
| 渐入过渡（onset fade） | `onsetFadeNotches` | 渐入窗口 150ms→30ms **在头 3 格平滑过渡** | 单格仍用 150ms，逐位不变 |

三者默认值都设为 0 时即回到 1.3.7 行为。

### 渐入过渡修的是什么（用户原话："起步到中段有个地方突然拉上去"）

原来窗口在 `active_` 处**一步硬切换**，实测第 2 格的加速度比第 1 格猛 **16 倍**：

| 每格最大加速度 | 修复前 | 修复后 |
|---|---|---|
| notch 1 | +0.25 /ms | +0.27 |
| **notch 2** | **+4.07** | **+1.07** |
| notch 3 | +3.51 | +2.61 |
| notch 4 起（稳态） | +3.66 → +4.79 | +5.11 → +6.87 |

改后在头 3 格**平滑递增**，台阶消失；两端（单格 / 稳态连滚）不变。

## 4. MIDI 编辑器竖直轴：`Delivery` 枚举

原来用两个独立 bool（`pitchQuantized` / `noCoast`）从动作表穿到 `Kick` → `Integrator` →
交付处共 8 处，动作表里还写成 `false, false, true`（不可读）。收敛为一个枚举：

```cpp
enum class Delivery {
  kStream,    // 连续相对值 + 正常滑行（其余全部）
  kStepUnits, // 整 7-bit 单位递进（MIDI 竖直【滚动】：按整行量化）
  kImmediate  // 整格一次交付、不滑行（MIDI 竖直【缩放】：固定像素刻度）
};
```

动作表因此自释义，反向动作**同步标注**：

| 动作 | delivery |
|---|---|
| 40432 竖直滚动 / **40661 反向** | `kStepUnits` |
| 40430 竖直缩放 / **40663 反向** | `kImmediate` |
| 40433/40660 水平滚动、40431/40662 水平缩放 | `kStream`（不变） |

按 **section 32060 + 竖直轴 + 名字里的 Scroll/Zoom** 判定，不写死 id。

### 竖直缩放"直接停"（用户要求）

该轴是**固定 2px 刻度**（实测原生每格行高严格 +2px，每次调用独立取整），滑行无处落脚。
故整格一次交付、跳过 glide —— 去掉收尾、直接停。**只此一轴**。
