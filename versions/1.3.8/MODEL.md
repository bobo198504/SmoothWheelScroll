# SmoothWheelScroll for REAPER 1.3.8

**扩展 1.3.7 的修复：MIDI 编辑器竖直轴的「竖直缩放」也套用同一处理。**
只改这一个轴，其它一律不变。DLL md5 `833b328783e21ad08841341915ecfc7d`。

## 为什么滚动和缩放是同一个问题

两者都在 **section 32060 的竖直（音高）轴**上，接收方都只能以**离散单位**表达，
而本插件的 fine 投递最小步进 `1/3840 格` 远小于那个单位 → 逐条消息被截断 → 收尾碎步一顿。

区别只在量化的单位不同：

| 轴 | 接收方的离散单位 | 实测 |
|---|---|---|
| 竖直**滚动**（40432 / 40661） | 一整**行** | 一行的像素高度（本机约 8–10px） |
| 竖直**缩放**（40430 / 40663） | 行高的**整像素** | 一格缩放把行高 62.46px → 31.23px（约减半），量化明显 |

所以用同一条规则即可：**该轴按整 7 位单位投递**（最小步进 `1/15 格`），余数仍跨帧累积。

## 改动（在 1.3.7 基础上）

- 动作表里把 **40430 / 40663**（竖直缩放正向 / 反向）也标上 `pitchQuantized`。
- `ClassifyByName` 的判据从「Scroll」扩为「**Scroll 或 Zoom**」，且仍限定
  `section == 32060 && !horizontal`，所以动作改名后照样生效。

## 与「参数传达原则」的关系（同 1.3.7）

本项目原则是「精度一律给足」。这里仍是一处**有界例外**，现在覆盖到 MIDI 竖直轴的
**滚动与缩放两者**，理由相同：该接收方**表达不出** `1/3840 格`，给足精度反而产生顿挫。
**边界扩大到此为止**：仅限 32060 的**竖直轴**（Scroll + Zoom），水平轴与其它所有面仍必须满精度。

## 待验收

竖直缩放的顿挫我**未能亲自复现**（该轴的变化是行高整像素，外部像素测量无法可靠区分

若手感不对，1.3.7 / 1.3.6 的代码与 DLL 均完整保留，可随时回退。
